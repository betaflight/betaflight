# HX711 MSP extension — wire version 1

Opt-in `USE_HX711` adds one read-only native MSPv2 command, `MSP2_SENSOR_HX711 = 0x3013`. The ID is allocated from the next free slot in the Betaflight-specific `0x30xx` block. Without the build define, normal MSP unsupported-command handling applies. No session, motor, tare, calibration or save commands are implemented.

Request payload: empty. Response: exactly 18 bytes, little endian.

| Offset | Type | Field | Units / meaning |
|---:|---|---|---|
| 0 | u8 | version | 1 |
| 1 | u8 | flags | bit 0 configured, bit 1 fresh, bit 2 saturated |
| 2 | i32 | raw | sign-extended 24-bit ADC count |
| 6 | u32 | sequence | increments once per completed conversion; wraps |
| 10 | u32 | age | milliseconds since acquisition; UINT32_MAX before first sample |
| 14 | u32 | time | acquisition timestamp from micros(); wraps |

Fresh means a conversion exists and its age is at most 250 ms. Saturated means raw is -8388608 or 8388607. A saturated sample may also be fresh; clients must reject saturated values for thrust/calibration. Configured only indicates GPIO initialization succeeded, not that a load cell is producing conversions. A frame is only accepted once DOUT is released high after the 25th pulse, so a stuck-low data line never produces a fresh sample and the last reading simply ages out. Timestamp and sequence belong to HX711 readings, not battery measurements. Sensor RATE remains a hardware choice (10/80 samples/s).

Example response payload:

```text
01 03 e6 5b ff ff 63 00 00 00 0a 00 00 00 39 30 00 00
```

Version 1, configured+fresh, raw -42010, sequence 99, age 10 ms, FC timestamp 12345 µs. With browser offset -10 and counts/gram -420, this is +100 g. Request frame (including MSPv2 CRC):

```text
24 58 3c 00 13 30 00 00 4a
```

The web app keeps fixed grams in logged measurements and calculates `(raw - offset) / countsPerGram` only for fresh, configured, nonsaturated readings and valid calibration. Browser captures use unique sequences to avoid treating repeated serial reads as independent sensor samples. Tare/calibration/save are local operations after standard MSP confirms disarmed/stopped motors. Save stores and verifies calibration in IndexedDB, keyed by the normal MSP UID response.

Normal motor/electrical operations use standard MSP_SET_MOTOR, MSP_MOTOR, MSP_ARMING_DISABLE, MSP_STATUS, MSP_BATTERY_STATE and optional MSP_MOTOR_TELEMETRY. There is no firmware-side motor-command watchdog in this feature. The old prototype 0x30F0–0x30F7 bench interface is incompatible and has been removed; install the HX711-only firmware when using this UI.

## Building and resources

Build with `make CONFIG=CLRACINGF4 EXTRA_FLAGS="-DUSE_HX711"`. Without the define the feature is disabled. Use ARM GNU 13.3.Rel1. Run the driver test through the standard Betaflight unit-test harness with `make test` (or `cd src/test && make test_hx711_unittest`).

Persistent PG 572 stores only `sckTag` and `doutTag`. Resources `HX711_SCK` and `HX711_DOUT` start unassigned. Release existing resource owners before assigning compatible 3.3 V GPIO. No target configuration is changed. Channel A/gain 128 and hardware-selected 10/80 Hz are supported.

On CLRACINGF4, with USB carrying MSP, release UART4 and move the HX711 onto its pins:

```text
resource SERIAL_TX 4 NONE
resource SERIAL_RX 4 NONE
resource HX711_SCK 1 A00
resource HX711_DOUT 1 A01
save
```

`save` persists the assignments and reboots the FC. Restore UART4 from a configuration backup once the pins are no longer used for the load cell.

## Validation

Bench validation is complete. An HX711 was wired to released UART4 pins on a CLRACINGF4 (SCK on TX4/PA0, DOUT on RX4/PA1), assigned with the resource commands above and exercised end to end through the web client on a physical thrust stand: pin assignment, raw counts, sign, sequence and freshness, tare, known-mass calibration and live thrust/current measurement all behave as designed, with 3.3 V logic and the module's RATE pin selecting 10 or 80 samples/s.

Host tests in `src/test/unit/hx711_unittest.cc` run the production driver against simulated GPIO and time for the pin, clocking, sign, saturation, stuck-low rejection, interrupt-protection, rate, sequence, freshness and timer-wrap cases. Re-check timing, noise and absolute accuracy on your own wiring and stand before trusting load-cell numbers.
